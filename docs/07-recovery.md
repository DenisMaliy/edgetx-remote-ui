# Відновлення пульта наосліп

> Цей документ написаний для людини, яка забула всі подробиці. Він не
> вимагає дивитися на екран пульта — екран розбитий, його нема.
> Усе, що тут написано, **перевірено на живому пульті 2026-07-25**.
> Неперевірене окремо позначено.

## Три речі, які треба знати

1. **Пульт неможливо зробити цеглиною.** Режим прошивки (DFU) сидить у
   самому процесорі, а не в програмі. Хоч би що ми залили, він відгукнеться.
2. **Заливка не потребує екрана.** Вимкнений пульт + USB = режим прошивки.
3. **Перед будь-яким записом знімається зліпок.** Він і є шлях назад.

## Що зараз у пульті

EdgeTX **2.12.2 (3673c518)**, завантажувач того самого релізу. Залито
2026-07-25 замість заводської 2.8.0 — див. `tasks/0002-upgrade-to-212.md`.

## Режими USB: що ПК бачить і як туди потрапити

| Режим | Пульт | Як увійти | ПК бачить |
|---|---|---|---|
| Прошивка (DFU) | **вимкнений** | просто встромити USB | `0483:df11` |
| Накопичувач | увімкнений | встромити USB, у вікні вибрати **другий** пункт | `0483:5720`, два томи: картка і диск на 2 МіБ |
| Джойстик | увімкнений | встромити USB, у вікні вибрати **перший** пункт (просто натиснути коліщатко) | `1209:4f54`, з'являється `/dev/input/js0` |

Другий пункт вибирається так: один клац коліщатком **вниз**, потім натиск.
Перевірено 2026-07-25.

Дрібна, але корисна ознака версії: у 2.8 джойстик звався
`Generic RM TX16S Joystick`, у 2.12.2 — `Generic Radiomaster TX16S Joystick`.

Вікно вибору з'являється тому, що в `RADIO/radio.yml` стоїть `USBMode: 0` —
«питати». Порядок пунктів (джойстик, потім картка) перевірено на ділі.

Щоб позбутися вікна, можна виставити режим примусово: витягнути картку,
вставити в кардридер і змінити `USBMode` у `RADIO/radio.yml`. Значення `0`
означає «питати» — це підтверджено спостереженням; решту значень звіряти з
переліком EdgeTX перед використанням, напам'ять їх не брати.

⚠️ Пульт переписує `radio.yml` при вимкненні. Редагувати картку — тільки на
**вимкненому** пульті, інакше правку затре.

## Доступ до картки

Найпростіше — увімкнути пульт, встромити USB і вибрати другий пункт.
Картка з'явиться як звичайна флешка. Другий шлях, незалежний від першого, —
меню завантажувача (тримати обидва горизонтальні тримери досередини і
ввімкнути живлення). ⚠️ Цей другий шлях **ми не перевіряли**; він описаний
як запасний.

Зняти копію:

```bash
rsync -rt /run/media/$USER/<том-картки>/ sd-backups/<назва>/
sync
```

Звірити копію з оригіналом:

```bash
cd <том-картки> && find . -type f -print0 | sort -z | xargs -0 md5sum > /tmp/card.md5
cd sd-backups/<назва> && md5sum -c --quiet /tmp/card.md5 && echo OK
```

## Зняти зліпок прошивки

Пульт **вимкнений**, USB встромлений.

```bash
lsusb | grep df11        # має бути 0483:df11

dfu-util -a 0 -d 0483:df11 -s 0x08000000:2097152 \
         -U sd-backups/firmware-original/<назва>.bin
```

Читання нічого не змінює в пульті. Займає близько хвилини.

## Залити прошивку

Пульт **вимкнений**, USB встромлений.

Спершу — рядок у журнал. Обов'язково, перед **кожним** записом. Це не
церемонія: коли пульт поведеться дивно, єдиний спосіб зрозуміти чому — знати
напевно, що саме в нього залито.

```bash
f=sd-backups/firmware-original/full-flash-dump.bin
printf '%s  %s байт  %s  %s\n' "$(realpath "$f")" "$(stat -c%s "$f")" \
  "$(date -r "$f" '+%F %T')" "$(md5sum "$f" | cut -c1-12)"
```

Потім заливка:

```bash
dfu-util -a 0 -d 0483:df11 -s 0x08000000:leave \
         -D sd-backups/firmware-original/full-flash-dump.bin
```

Ознака успіху в кінці виводу:

```
File downloaded successfully
Submitting leave request...
```

Одразу після цього **звірити**: витягнути й встромити USB (пульт лишається
вимкненим), перечитати пам'ять і порівняти:

```bash
dfu-util -a 0 -d 0483:df11 -s 0x08000000:2097152 -U /tmp/verify.bin
cmp /tmp/verify.bin sd-backups/firmware-original/full-flash-dump.bin \
  && echo "ЗБІГ ПОБАЙТОВО"
```

Без цієї звірки заливка не вважається виконаною.

⚠️ **Якщо заливали не зліпок на 2 МіБ, а файл прошивки** (наприклад
`tx16s-3673c51.bin`, 1 595 376 байтів), порівнювати можна **тільки перші N
байтів**, де N — розмір цього файлу:

```bash
cmp -n 1595376 /tmp/verify.bin .../tx16s-3673c51.bin && echo "ЗБІГ"
```

Повний дамп не зійдеться ніколи: `dfu-util` стирає лише ті сторінки, у які
пише, і хвіст флеша зберігає уламки попередньої прошивки. Це нешкідливо —
той код не виконується. Перевірено 2026-07-25: після оновлення на 2.12.2 на
зсуві `0x1f490d` лишився рядок старого завантажувача 2.7.1.

## Дізнатися, що зараз у пульті, не вмикаючи його

Зняти зліпок (див. вище) і подивитися рядки версії. Метод не залежить від
того, чи пульт узагалі завантажується:

```bash
strings -t x <зліпок>.bin | grep -i edgetx-tx16s
```

Завантажувач лежить близько зсуву `0x1ac`, застосунок — близько `0x201c0`.
Приклад справного виводу після оновлення:

```
    1ac BOOT10edgetx-tx16s-v2.12.2 (3673c518)
  201c0 edgetx-tx16s-v2.12.2 (3673c518)
```

## Повернутися на 2.8.0

Той самий порядок, що й будь-яка заливка, але файл — старий еталон
`sd-backups/firmware-original/full-flash-dump.bin` (2 МіБ, `bab1d2a3…`).
Він накриває весь флеш, тому звірка тут повна, без `-n`.

⚠️ Картку теж доведеться повернути: у пульті зараз вміст під 2.12, а
`radio.yml` у ньому вже у форматі 2.12. Копія під 2.8 —
`sd-backups/upgrade-2.12.2/card-before/`, звірена сумами.

## Перевірити, що пульт живий

1. Витягнути USB, увімкнути пульт. Має бути звук старту.
   ⚠️ Картка мусить стояти в пульті — усі звуки лежать на ній.
2. Встромити USB до ввімкненого пульта, натиснути коліщатко (перший пункт —
   джойстик). Має з'явитися `/dev/input/js0`.
3. Переконатися, що стіки справді рухаються, а не просто пристрій
   зареєструвався:

```bash
python3 tools/jswatch.py      # крутити обома стіками поки йде відлік
```

Докладніше — два інші інструменти:

```bash
python3 tools/jsinfo.py       # скільки осей і кнопок, справжні діапазони
python3 tools/axprobe.py      # 22 с запису: скільки рівнів видала кожна вісь
```

Справний вивід `jsinfo.py` на 2.12.2 (виміряно 2026-07-25):

```
осей:   8
кнопок: 24
кожна вісь: від 0 до 2048   рівнів 2049
```

⚠️ **Кількість осей — сама по собі ознака версії.** На 2.8 їх видно **сім**,
а не вісім: у дескрипторі тієї прошивки двічі оголошено один і той самий тип
осі (`Slider` замість `Slider` + `Dial`), і Linux зліплює два останні канали
в один. Виправлено у 2.9. Межа значення там теж інша — 2047, не 2048.

Тобто «вісім осей і межа 2048» — це незалежний доказ, що працює саме 2.12.x,
який не потребує ні картки, ні коректного вимкнення.

Робочий результат: чотири осі з розмахом близько 65 000 (два стіки),
решта осей нерухома, поки не чіпати повзунки.

## Пастки

**«Device's firmware is corrupt»** у виводі `dfu-util` — це **не** про наш
пульт. Так процесор відповідає завжди, коли він у режимі прошивки без
запущеної програми. Повідомлення з'являлося ще до першого запису.
`dfu-util` сам скидає цей стан і працює далі.

**Пульт гасне після заливки.** Хвіст `:leave` наказує вийти з режиму
прошивки й запустити програму, а живлення тримався USB — тому пульт просто
згасає і зникає з шини. Це нормально, вмикати треба кнопкою.

**Правило udev.** Файл `/etc/udev/rules.d/45-st-dfu.rules` уже стоїть і
працює — права `0666`, група `uucp`, `dfu-util` пише без `sudo`. Якщо
пропаде, див. `docs/10-arch-linux.md`.

**Якщо DFU не з'являється.** Перевірити, що кабель із даними, що пульт
справді вимкнений, і що жодна програма не тримає пристрій.

## Журнал перевірки

**2026-07-25.** Знято копію картки (1152 файли, звірено побайтово за
контрольними сумами) і зліпок пам'яті. Зліпок отримано двома незалежними
шляхами — через `dfu-util` і через диск прошивки, що його віддає пульт, —
обидва результати збіглися до байта.

Цикл «стерти → записати → перечитати → звірити» пройдено **двічі**, обидва
рази з побайтовим збігом. Після кожного циклу пульт вмикався зі звуком,
віддавав себе в ПК як джойстик, чотири осі проходили повний розмах.

Жодного разу за всю перевірку екран пульта не знадобився.

**2026-07-25, оновлення 2.8.0 → 2.12.2** (задача 0002). Перед записом знято
свіжий зліпок — збігся з еталоном 2.8 побайтово. Порядок був такий: спершу
записали вміст картки під 2.12 (пульт ще на 2.8, режим накопичувача), потім
залили прошивку через `dfu-util`. Так перший запуск 2.12 одразу побачив
правильну картку і мігрував налаштування один раз, а не двічі.

Після заливки перші 1 595 376 байтів пам'яті збіглися із залитим файлом
побайтово. Пульт завантажився, і всі три докази життя зійшлися: рядки
`v2.12.2` у зліпку, `semver: 2.12.2` у `radio.yml` після коректного
вимкнення, чотири осі джойстика з повним розмахом 65 534.

Калібрування стіків пережило оновлення повністю. Імена в `calib:`
перейменувалися за новою схемою (`Rud→LH`, `Ele→LV`, `Thr→RV`, `Ail→RH`,
`S1→P1`, `6POS→P2`, `S2→P3`, `LS→SL1`, `RS→SL2`), але всі числа збіглися до
одного. Це не випадковість: у 2.12 читач `calib` має таблицю старих імен для
кожної цілі — `radio/util/hw_defs/legacy_names.py`.

Екран і тут не знадобився жодного разу.

## Етап 0. Довести, що пульт можна прошити наосліп ⚠️

**Без цього етапу решта плану не має сенсу.** Якщо ми не вміємо залити
прошивку і повернути назад робочу — ми не маємо права експериментувати.

**Етап закрито 2026-07-25** — задачі [0001](../tasks/0001-blind-flash-proof.md)
і [0002](../tasks/0002-upgrade-to-212.md), обидві прийняті рецензією.

- [x] 0.1 Зняти повну копію SD-картки на ПК.
- [x] 0.2 Зберегти поточну прошивку (версія, збірка) — точка відкату.
- [x] 0.3 Дістатися картки наосліп. ⚠️ Зроблено **іншим шляхом**, ніж
      планувалося: не через тримери й завантажувач, а з увімкненого пульта —
      USB, друге меню в списку. Працює й перевірене. Шлях через тримери
      лишився неперевіреним, він записаний як запасний.
- [x] 0.4 DFU працює: пульт вимкнений + USB = `0483:df11`, `dfu-util` пише без
      `sudo`. Спосіб зафіксовано в `docs/07-recovery.md`.
- [x] 0.5 Залито немодифікований еталонний зліпок; пульт живий — звук старту,
      джойстик у ПК, чотири осі з повним розмахом.
- [x] 0.6 `docs/07-recovery.md` написано.
- [x] 0.7 (понад план) Пульт оновлено 2.8.0 → **2.12.2**, тобто до тієї версії,
      проти якої пишеться патч. Калібрування вціліло, моделі на місці.

**Критерій виходу:** ✅ прошивка залита й повернута назад двічі з побайтовою
звіркою, процедура задокументована.

**Якщо не вийшло:** зупиняємось і думаємо. Варіанти: тимчасово підключити
зовнішній дисплей до шлейфа, позичити робочий пульт для експериментів,
або перейти на шлях без зміни прошивки (Lua + serialWrite).

## Етап 1. Розробка в симуляторі

Швидкий цикл без заліза. EdgeTX збирається під ПК і використовує той самий
код GUI.

- [x] 1.1 `tools/setup-upstream.sh` — клонує EdgeTX, закріплено на **тезі
      `v2.12.2`** (та сама версія, що залита в пульт; гілка `2.12` не годиться,
      бо її голова їде далі за реліз).
- [x] 1.2 Зібрати симулятор цілі `X10` (SDL2), переконатися, що працює.
      Зроблено — `docs/11-simulator.md`, задача 0003.
- [x] 1.3 Каркас `remote_ui/`: протокол, CRC, кадрування. Юніт-тести на кадрування.
      Зроблено — задача 0004.
- [x] 1.4 Захоплення екрана **гачком `remoteUiOnFlush`** + RLE. У симуляторі
      транспорт — TCP-сокет замість UART. (Порівняння буферів скасовано
      2026-07-26 — не працює на TX16S, розбір у `docs/02-architecture.md`.)
- [x] 1.5 Тестовий клієнт `tools/test_client.py`: показує вікно з екраном пульта.
- [x] 1.6 Емуляція вводу: клавіші → енкодер → сенсор. Зроблено — задача 0007.
      Критерій виходу з етапу закрито пройденим сценарієм зі знімками.
- [ ] 1.7 ⏸ **Відкладено 2026-07-26, рішення людини.** Прогнати збірку симулятора
      для 3–4 різних цілей (X10, T18, PL18, ЧБ), переконатися, що `HELLO`
      коректно описує різне залізо.

      Причина відкладення: підтримка чужих пультів — далека перспектива і не
      факт, що вона взагалі знадобиться. Крок працює на майбутніх користувачів,
      тоді як етап 2 працює на власника цього пульта. Відкладення нічого не
      псує: борги кроку акуратно зібрані й нікуди не подінуться —
      параметр «крок рядка» для гачка захоплення (`docs/05-hooks.md`, пункт 5),
      `USE_HATS_AS_KEYS` на PL18/NV14/EL18, розбіжність одиниць `rotencDt` у
      драйвері PL18 (кандидат в окремий PR у EdgeTX).

**Критерій виходу:** у симуляторі можна повністю керувати пультом через
тестовий клієнт, включно з відкриттям меню Lua-скрипта.

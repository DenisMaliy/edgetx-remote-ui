# ТЗ — Технічне завдання

Версія 1.0 · статус: чернетка для узгодження

## 1. Передумова

RadioMaster TX16S справний, але дисплей фізично розбитий. Пульт неможливо
налаштувати: недоступні системне меню, налаштування моделі, меню Lua-скриптів.

Ремонт дисплея свідомо відхилений — ціль проєкту не «полагодити», а
«отримати навички і зробити річ, якої в EdgeTX немає».

## 2. Ціль

Повнофункціональна заміна дисплея: віддалений інтерфейс (remote UI), який
показує зображення екрана пульта на зовнішньому пристрої і передає назад ввід.

Ключова властивість: **прозорість**. Прошивка не відтворює інтерфейс, а
транслює справжні пікселі. Тому підтримується будь-що, що вміє малювати на
екран, включно зі сторонніми Lua-скриптами, про існування яких ми не знаємо.

## 3. Область застосування

### Входить у MVP
- Трансляція кадрового буфера TX16S (480×272, RGB565) на зовнішній клієнт.
- Емуляція сенсорного вводу (touch): натиск, ковзання, відпускання.
- Емуляція фізичних клавіш і енкодера.
- Транспорт: UART (AUX1) через міст ESP32 → Wi-Fi → браузер.
- Робота з телефона (Android/iOS) і ПК без встановлення застосунку — браузер.

### Не входить у MVP, але закладається в архітектуру
- USB CDC як другий транспорт.
- Файлові операції (перегляд/редагування `radio.yml`, моделей) поверх протоколу.
- Підтримка інших кольорових пультів на EdgeTX.
- Підтримка ЧБ-пультів.
- Прийняття у upstream EdgeTX.

### Не входить взагалі
- Заміна EdgeTX власним інтерфейсом.
- Передача відео з камери / FPV.
- Керування моделлю з телефона (тільки налаштування, не пілотування).

| ID | Вимога | Пріоритет |
|---|---|---|
| F-01 | Прошивка передає змінені ділянки екрана зовнішньому клієнту | must |
| F-02 | Клієнт отримує повний кадр на запит (після переконнекту) | must |
| F-03 | Клієнт передає події сенсора з координатами | must |
| F-04 | Клієнт передає натиск/відпускання будь-якої фізичної клавіші | must |
| F-05 | Клієнт передає кроки енкодера, включно з натиском на нього | must |
| F-06 | Клієнт передає події тримерів | should |
| F-07 | Пакет `HELLO` описує залізо: роздільність, формат, перелік клавіш | must |
| F-08 | Протокол має номер версії; клієнт коректно працює зі старшою прошивкою | must |
| F-09 | Функція вмикається/вимикається без перезбирання (режим порту) | must |
| F-10 | Стан пульта (модель, батарея, RSSI) передається окремо від пікселів | could |

## 5. Нефункціональні вимоги

| ID | Вимога | Значення |
|---|---|---|
| N-01 | Затримка від дотику до відгуку на екрані | < 150 мс |
| N-02 | Частота оновлення при типовій навігації меню | ≥ 15 кадр/с |
| N-03 | Час повної перемальовки екрана | < 0.5 с |
| N-04 | Додаткове навантаження на процесор пульта | < 10% |
| N-05 | Відсутність впливу на керування моделлю | 0 пропущених кадрів мікшера |
| N-06 | Приріст обсягу прошивки | < 20 КБ |
| N-07 | Просідання дальності радіолінка при ввімкненому Wi-Fi | не актуально (зовнішній модуль); перевірити, якщо повернетесь до внутрішнього |

N-05 критичний. Пульт керує літальним апаратом; будь-яка функція, що
ставить це під загрозу, вимикається або викидається.

## 6. Обмеження

- **C-01.** Екран не працює → усі налаштування пульта на етапах 0–2 робляться
  правкою файлів на SD-картці через режим завантажувача.
- **C-02.** Мікшер EdgeTX працює з періодом 5 мс і має пріоритет. Наш код
  ніколи не блокує головний цикл, ніколи не чекає на USB/UART.
- **C-03.** Сторожовий таймер (watchdog) не прощає зависань.
- **C-04.** Флеш-пам'ять STM32F429 майже вичерпана поточним EdgeTX.
- **C-05.** Пам'ять моста: повний кадр 255 КБ не влазить у жодну з наявних
  плат ESP32 → архітектура моста обов'язково потокова, без накопичення.

## 7. Критерії приймання MVP

1. Пульт вмикається, телефон показує екран EdgeTX у реальному часі.
2. Дотиком на телефоні можна пройти: головний екран → системне меню →
   налаштування апаратури → змінити режим порту → вийти зі збереженням.
3. Дотиком можна відкрити меню Lua-скрипта (ELRS-конфігуратор) і змінити в
   ньому значення.
4. Бокові кнопки на телефоні повторюють SYS / MDL / TELE / RTN / ENTER та
   прокрутку енкодера.
5. Перевірено з увімкненим передавачем: телеметрія й керування не постраждали.
6. Пульт залишається повністю робочим при вимкненому Wi-Fi/мості.

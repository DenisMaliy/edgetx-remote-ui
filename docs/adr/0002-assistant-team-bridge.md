# ADR-0002. Міст між асистентом і командою через файли задач

- **Дата:** 2026-07-25
- **Статус:** прийнято
- **Учасники:** людина, асистент

## Контекст

До цього схема була така: обговорення в окремому чаті, звідти людина
вручну переносила задачу в Claude Code, потім копіювала відповідь назад.
Асистент виступав фільтром і контролером.

Схема мала вбудовану ваду: **асистент оцінював роботу команди за звітом
самої команди**. Перевірка звіту за допомогою звіту. Плюс копіпаст
деградував саме на складних етапах, коли фільтр потрібен найбільше.

## Розглянуті варіанти

### Варіант А — лишити копіпаст
- Плюси: нічого не треба будувати; людина пропускає все через себе і
  краще вчиться.
- Мінуси: асистент не може нічого перевірити; два джерела правди
  розходяться; втома на довгих логах; затримка вбиває швидкі цикли.

### Варіант Б — асистент як субагент команди
- Плюси: усе в одній сесії, вбудовано.
- Мінуси: **не працює**. Субагент відповідає один раз і зникає, а роль
  вимагає тривалого діалогу з людиною.

### Варіант В — два змінні файли (`current_prompt.md` / `current_result.md`)
- Плюси: просто; копіпасту немає.
- Мінуси: файли перезаписуються, історія зникає — тобто зникає саме те,
  заради чого все затівалось: можливість побачити, де рішення розійшлося
  з результатом.

### Варіант Г — Agent Teams
- Плюси: вбудована координація, спільний список задач, блокування файлів.
- Мінуси: експериментальна фіча, немає `/resume`, помітно дорожча за
  токенами. Для наших етапів 0→1→2, які суворо послідовні, паралелити
  нічого — платимо за швидкість, якої не отримаємо.

## Рішення

**Варіант Д (обраний):** дві окремі сесії Claude Code в одному
репозиторії, міст — нарощуваний журнал задач у `tasks/`, одна задача —
один файл, три зони з різними власниками.

Ключове доповнення, без якого решта не має сенсу: правило
**«рецензія тільки за доказами, ніколи за звітом»**, записане в
`docs/ROLE-assistant.md` і в команду `/task-review`. Асистент має той
самий доступ до репозиторію, що й команда, тому зобов'язаний перевіряти
`git diff` і читати змінені рядки сам.

Agent Teams не відкидається — вмикати з етапу 2.6, коли з'явиться справді
паралельна робота (прошивка моста і веб-клієнт).

## Наслідки

- З'являються `tasks/`, `docs/ROLE-assistant.md`, `state/ASSISTANT.md`
  і чотири команди: `/assistant`, `/task-new`, `/task-report`, `/task-review`.
- Таблиця власності артефактів стає обов'язковою — інакше двовладдя.
- Людина читає не чат, а diff. Історія рішень лишається в git назавжди.
- Дозволи Claude Code діють на проєкт, а не на сесію, тому «асистент лише
  читає» — це домовленість у файлі ролі, а не механічний бар'єр.
  Реальний запобіжник — перегляд diff людиною перед комітом.

## Умови перегляду

- Якщо оформлення задач почне з'їдати більше часу, ніж економить —
  розширити перелік того, що йде повз міст.
- Якщо асистент почне переказувати звіти замість перевірки — посилити
  формулювання в `/task-review` або винести перевірку в окремий
  субагент із доступом лише до `git diff`.
- Коли з'явиться паралельна робота — переглянути на користь Agent Teams.

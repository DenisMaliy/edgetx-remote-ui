# Міст ESP32

Приймає UART 921600 від AUX1 пульта і віддає у WebSocket. І назад.

Міст **тупий на рівні вмісту**: не знає ні розміру екрана, ні RLE, ні того,
що таке плитка. Уся логіка — у прошивці пульта і в клієнті.

⚠️ Але **межі пакетів він знає**, і це не суперечить сказаному вище. Три
причини, кожної з яких вистачило б самої: відкидати можна лише цілими
пакетами (інакше клієнт втратить іще до 4096 байтів на ресинхронізації);
заміри вимагають розрізняти, скільки плиток відкинув міст, а скільки пульт;
бита по CRC плитка не варта ефіру. Подробиці — у `main/framing.h`.

## Середовище

**`idf.py` на ESP-IDF v5.5.4**, який стоїть у `~/.espressif` (крок 2.6a).
PlatformIO цей проєкт не збирає — там Arduino-середовище людини, і мішати їх
означає два шляхи до компілятора і дві версії IDF. Обґрунтування —
`state/DECISIONS.md`, ADR-0004 лишається чинним по суті (чистий IDF без
Arduino), змінився лише збирач, що сам ADR і дозволяє.

⚠️ **Крім IDF потрібні `node` і `pnpm`** — клієнт мініфікується на збірці
(задача 0022, критерій 8.3: без цього сторінка з'їдає 85 КБ вільної купи зі
105). Без них збірка **не почнеться** і скаже, чого бракує; тихого відкату до
немініфікованого клієнта немає навмисно.

```bash
. ~/.espressif/tools/activate_idf_v5.5.4.sh   # точково, у своєму терміналі
pnpm -C ../../webui install                   # один раз: пінований esbuild

# ESP32 DevKit v1 — плата для розробки
idf.py set-target esp32
idf.py build
idf.py -p /dev/ttyUSB0 flash monitor

# ESP32-C3 SuperMini — окрема тека збірки й окремий sdkconfig
idf.py -B build-c3 -DSDKCONFIG=sdkconfig.c3 -DIDF_TARGET=esp32c3 build
```

⚠️ Глобального `IDF_PATH` у системі немає і бути не повинно: саме він
змушує один набір інструментів мовчки підмінювати інший. Активація —
точкова, у тому терміналі, де збираєш.

⚠️ `sdkconfig` і `sdkconfig.c3` **не в git**: вони згенеровані. Джерело
правди — `sdkconfig.defaults` і `sdkconfig.defaults.esp32c3`. Змінив їх —
видали `sdkconfig` і збери наново, інакше зміни не підхопляться.

## Що всередині

| Файл | Про що |
|---|---|
| `main/bridge_cfg.h` | усі налаштовувані числа й **уся** специфіка плати |
| `main/framing.c` | кадрування, CRC, обнулений `INPUT_STATE` |
| `main/uart_link.c` | канал до пульта |
| `main/ws_bridge.c` | HTTP-сторінка, WebSocket, стан з'єднання |
| `main/wifi_ap.c` | точка доступу, потужність, вимикання |
| `main/main.c` | дві задачі й черга між ними |
| `test/test_framing.c` | перевірка кадрування на комп'ютері, без ESP32 |

Клієнт лежить у `webui/` і вбудовується звідти — **без копії тут**. Та сама
причина, з якої наш код в EdgeTX підключається через symlink: другий
примірник рано чи пізно правлять, а потім втрачають.

```bash
cd test && cc -std=c11 -Wall -Wextra -fsanitize=address,undefined \

# протокол клієнта — теж на комп'ютері
node ../../webui/proto_test.js
```

## Гарячий шлях

**Приймання не має права блокуватись.** На 921600 апаратна черга UART
наповнюється за 1.4 мс, тож шлях розрізаний надвоє скінченною чергою:

```
UART ──► rx_task ──► черга ──► ws_tx_task ──► Wi-Fi
         (не чекає)  (скінченна) (має право чекати)
```

Переповнення черги **і є** ухвалене «захлинувся WebSocket — плитки
відкидаються». Місце, де міст щось відкидає, рівно одне, і воно рахується.

## Перше підключення до пульта

⚠️ **Не за цим розділом, а за [BRINGUP.md](BRINGUP.md)** — там покрокова
процедура з висновку `hw-integration`: порядок фаз, заміри мультиметром на
кожному кроці, конденсатори, і головне правило «USB від ПК і 5 В від пульта —
ніколи одночасно».

## Розпіновка

Піни — у `main/bridge_cfg.h`, правити там, не в коді.

| Плата | RX моста | TX моста | Порт |
|---|---|---|---|
| DevKit v1 | GPIO16 | GPIO17 | UART1 |
| C3 SuperMini | GPIO4 | GPIO5 | UART1 |

⚠️ **Хрест обов'язковий:** TX пульта → RX моста.

⚠️ На C3 навмисно **не** GPIO20/21, хоча вони стояли в старому плані: це
штатні піни UART0, і ПЗП-завантажувач друкує туди свій журнал ще до того,
як наш код отримає керування. Пульт отримував би сміття в AUX1 при кожному
перезавантаженні моста.

⚠️ Розпіновка C3 ще не проходила `hw-integration` — перед першим
підключенням C3 це обов'язково.

## Живлення

Живлення від 5 В пульта, конденсатор **1000 мкФ** біля модуля плюс
керамічний 100 нФ. Без них імпульси Wi-Fi у 300–500 мА перезавантажуватимуть
плату, і виглядатиме це як вада коду.

## Мережа

Точка доступу `TX16S-RemoteUI`, пароль `tx16sremote`, сторінка на
`http://192.168.4.1/`. Закрита паролем навмисно: через неї керують пультом.
Змінюється в `bridge_cfg.h`.

Потужність передавача знижена до 8.5 дБм — до телефона метр, а поруч працює
радіомодуль пульта. Вимкнути Wi-Fi зовсім: `POST /api/wifi/off`; увімкнути
назад — перезавантаженням моста.

Лічильники: `GET /api/stats`.

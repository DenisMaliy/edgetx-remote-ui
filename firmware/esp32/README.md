# Міст ESP32

Приймає UART 2 Мбод від AUX1 пульта, віддає у WebSocket. І назад.

Міст **тупий**: не інтерпретує вміст пакетів, тільки перекладає між
транспортами. Уся логіка — у прошивці пульта і в клієнті.

## Середовище

PlatformIO. Готовий каркас — `platformio.ini`, три середовища:

| Середовище | Що це |
|---|---|
| `s3_arduino` | Arduino core 3.x, швидкий старт (за замовчуванням) |
| `s3_idf` | чистий ESP-IDF |
| `s3_arduino_usbcdc` | те саме, що перше, + логи через нативний USB S3 |

Вибір середовища ще не зафіксований остаточно —
див. `docs/adr/0001-esp32-framework.md`.

```bash
pio run -e s3_arduino            # зібрати
pio run -t upload                # прошити
pio run -t uploadfs              # залити webui/ у LittleFS
pio device monitor               # логи
```

## Незалежно від вибору середовища

**Гарячий шлях робиться драйвером ESP-IDF.** `uart_driver_install()` з
кільцевим буфером на щонайменше два повні кадри. Arduino `HardwareSerial`
на 2 Мбод втрачає дані — це не питання смаку.

Arduino core 3.x побудований на ESP-IDF 5.x, тому IDF-функції доступні
прямо з Arduino-скетчу. Тобто «Arduino для зручності, IDF для швидкості» —
цілком робоча комбінація, а не компроміс.

## Плата

ESP32-S3 із зовнішньою антеною. Це не забаганка: див. `docs/06-hardware.md`,
розділ про радіочастотну сумісність з внутрішнім модулем пульта.

Бонус S3: власний USB. Логи йдуть по USB-C і не заважають потоку кадрів
на UART.

## Розпіновка

Піни задані в `build_flags` (`PIN_UART_RX` / `PIN_UART_TX`) — правити там,
не в коді. Не забути перехрестити: TX пульта → RX моста.

Каркас коду створюється на етапі 2.6.
